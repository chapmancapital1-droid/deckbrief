The Pipeline

Every Foundry Pack is manufactured the same way.

One repeatable process — not one-off custom builds. Each step produces a defined output that feeds the next. Humans hold the release gates.

01
Business Intent

Describe the business

"Build a residential cleaning company system." The Architect captures intent, industry, and the operating problem to solve.

Output: Foundry project + business brief
02
Research

Build the industry dossier

Customers, workflows, competitors, terminology, and risks — with sources — so the system reflects how the business actually runs.

Output: Industry dossier
03
Blueprint

Design the operating model

Offers, roles, value streams, revenue model, and metrics become a Business Blueprint the customer can review.

Output: Business Blueprint
04
Product Recipe

Resolve the Genome

Required capabilities map to existing, versioned modules. Compatible versions are locked into a reproducible recipe.

Output: Product recipe + lockfile
05
Composition

Assemble the repository

Approved modules, vertical overlay, config, and branding generate a reproducible source repository — derived, never copy-pasted.

Output: Build candidate
06
Verification

Prove it's production-ready

Tests, security scans, license checks, migrations, SBOM, and provenance. "Production-ready" is a set of passed gates, not a launch.

Output: Verification report
⚑
Human release gate — product, engineering, security, and licensing sign-off required before anything ships.
07
Release

Package and version

A signed, versioned release: source package, containers, documentation, and the operating playbook.

Output: Approved release artifact
08
Deploy & Learn

Launch and improve

Managed cloud or approved self-hosting. Reliability, adoption, and outcomes flow back and improve the Business Genome.

Output: Live system + telemetry

The Business Genome

Why the tenth product is mostly assembly.

Every reusable capability is a governed module — with data, API, permissions, events, tests, docs, and an upgrade path. Products are derived from a manifest, not copied. That means a security fix reaches every product, and customers can be updated safely.

Not a copy machine. "Need login? Copy it" creates fork hell. The Composer reads a recipe, resolves compatible versions, and records exactly what shipped — so updates stay possible.
business.genome.yaml
 
family: local-service-company
vertical: residential-cleaning
 
capabilities:
  - identity@1.0
  - crm@1.2
  - scheduling@1.3
  - recurring-services@1.0
  - payments@1.2
  - reviews@1.0
 
deployment:
  mode: managed-cloud
  isolation: single-tenant
